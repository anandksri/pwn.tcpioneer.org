# AI Coding Rules

1. Do not rewrite working functionality unnecessarily.
2. Do not change the database schema without explicit instruction.
3. Do not create duplicate components.
4. Reuse existing components before introducing new ones.
5. Keep TypeScript strict and error-free.
6. Avoid `any` unless absolutely required and justified.
7. Do not use inline styles unless there is no practical alternative.
8. Use Tailwind consistently across the app.
9. Follow the PWN.TCPIONEER design tokens.
10. Do not use random gradients or decorative neon effects.
11. Do not introduce excessive rounded corners.
12. Do not add glassmorphism patterns.
13. Avoid unnecessary dependencies.
14. Check existing code before creating a new file.
15. Fix TypeScript errors before moving on.
16. Run lint and type check after major changes.
17. Do not break authentication.
18. Do not break existing routes.
19. Keep components small and reusable.
20. Prefer server components unless client-side interactivity is required.
21. Use `use client` only when necessary.
22. Never expose secrets.
23. Never hardcode production credentials.
24. Do not replace real data with mock data unless explicitly requested.
25. Do not modify unrelated files.
